# KNOWN ISSUES
- Shared palette definitions and OKLab sampling have hardware-free coverage; the Visuals selector saves the palette and the shared shader samples it before brightness. Tests verify texture bytes and source wiring, not GLSL compilation or resulting colors on Windows/Mac GPUs. Appearance and measured performance remain unverified; see DESIGN.md milestone 5 for hardware checks.
- No Projection Studio shader, including the six new effects, has been visually checked on a projector or benchmarked at 1080p/4K. All 41 animation IDs have hardware-free palette/audio/profile/source checks and the new loops have fixed bounds. Low/Medium/High and adaptive fallback are implemented with canvas caps, reduced fBm work, and timing hysteresis; tests prove the policy logic, not actual GPU cadence. No appearance or 60fps claim is verified.
- Current animation tests verify IDs, profile bounds, source wiring, and loop bounds, not actual GLSL compilation on Windows or Mac GPUs. The local Electron launch aborted before rendering; successful cross-platform CI does not prove the shaders look right on real hardware. Run the six new effects and Ripple Reveal by eye on both platforms.
- Projection bulb snapshots previously aliased the device RGB array, and the restore patch omitted a valid brightness value of `0`. Fixed by cloning RGB on snapshot/restore and checking for undefined/null; evidence: `node test/projection.js` mutates the device colour and verifies restoration of the independent saved RGB and zero brightness.
- Room photo import could finish after a layout switch and attach the photo to the wrong project. Fixed by capturing the initiating project; evidence: `node test/projection.js` confirms a delayed result updates only its originating object and does not repaint the selected project.
- A beat-scheduled manual animation change could fire after the user switched layouts, repainting/saving the wrong project while mutating a detached shape. Fixed with a current-project and shape-membership guard; evidence: `node test/projection.js` verifies stale scheduled work is canceled after a project switch.
- Projection Studio also discarded snapshots after a restore command failed: `manager.apply()` returns `{ failed }` rather than rejecting. Fixed by keeping failed/unavailable snapshots, exposing per-bulb restore failures, and allowing Stop to retry from the Lights tab; evidence: `node test/projection.js` simulates a failed restore followed by a successful retry. Actual provider reconnect/retry remains unverified.
- Native shutdown previously skipped a retry when only failed snapshots remained and Projection Lights was inactive. Fixed so close/quit invokes Stop whenever snapshots remain; source syntax and the Stop retry unit case pass, but actual shutdown/provider restoration requires app and bulb hardware.
- Projection Studio light sync discarded a bulb's original state when repeated output failures dropped that bulb from active sync. Fixed in `src/main/projlights.js`; evidence: `node test/projection.js` injected four provider failures and confirmed Stop still attempted to restore the original on/brightness/colour state.
- Picture-following lights previously eased toward the latest frame but could accumulate a large jump between commands, especially when a cloud bulb had to wait for its brand interval. The first output also did not start from the saved live colour. Fixed by seeding ramps from the original RGB/white state and capping regular RGB/brightness steps; evidence: `node test/projection.js` verifies command deltas, per-brand intervals for WiZ/Cync/Hubspace, and original-state restoration after Stop. Real bulb smoothness remains unverified.
- Projection Studio's debounced save previously read `pj.cur` only when the timer fired, so switching layouts before the delay could save the wrong project. Fixed with a per-project snapshot queue and a flush before deletion; evidence: `node test/projection.js` confirms same-project edits coalesce and two projects save their own captured state.
- Native quit (including macOS Cmd+Q) could bypass the main-window close restore path, and the close path could destroy the app after four seconds while a slow restore was still running. Quit now waits for active drivers, and Projection Lights waits for in-flight writes before restoring; evidence: `node test/projection.js` verifies command ordering and idempotent concurrent Stop. Actual shutdown and bulb restoration remain unverified because Electron aborts before opening here.
- Reopening Projection Studio output could let the old window's `closed` event clear the replacement window reference. The handler now checks window identity; source syntax passes `node --check`, but reopening on real displays remains unverified without an Electron run.
- README previously said there were 21 Projection Studio animations; the current preset list now contains 41 (35 original IDs plus six added effects). README count matches `LumenProj.PRESET_IDS.length` (41).
- macOS does not provide system sound capture. Projection Studio now labels its Mac behavior and switches to Microphone when no system audio track is supplied; policy tests pass in `node test/projection.js`, but real Mac permissions and capture remain unverified. Effects still requires manual microphone selection.
- Local `npm test` is blocked in this environment by the WiZ simulator loopback address: it fails binding `127.0.0.70:38899` (`EPERM` sandboxed; `EADDRNOTAVAIL` unsandboxed). The hardware-free Projection Studio test passes independently.
- After `npm ci`, `npm start` exits with Electron `SIGABRT` before the UI is visible; the captured stack trace does not identify a cause. Interactive Studio behavior has not yet been observed here.
- Mac: system-sound capture for Effects is unavailable (Windows-only loopback in src/main/main.js); Mac falls back to the microphone.
- Mac: the first build (identity null, no signature) showed "Lumen is damaged and can't be opened" on the owner's Mac (reported 2026-11-15). Workaround: `xattr -cr /Applications/Lumen.app`. Fix attempted: `mac.identity` set to "-" (ad-hoc signing) in package.json; UNVERIFIED until the next release build is tried on a Mac. Even when fixed the app is not notarized, so first launch needs right-click > Open. Windows build is unsigned too (SmartScreen may warn).
- `npm test` currently covers only the 3 WiZ tests; other test files are missing from the repo.
- The Cync relay certificate is expired and mismatched; the user must tick "Trust the Cync relay's certificate" (pinned). Documented, deliberate.
- Cync allows one relay session per account; opening the Cync phone app drops Lumen's session until the next command.
- Hubspace and Cync integrations are unofficial/reverse-engineered and can break if the vendors change their cloud.
