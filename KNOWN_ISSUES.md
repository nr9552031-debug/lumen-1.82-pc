# KNOWN ISSUES
- Projection Studio light sync discarded a bulb's original state when repeated output failures dropped that bulb from active sync. Fixed in `src/main/projlights.js`; evidence: `node test/projection.js` injected four provider failures and confirmed Stop still attempted to restore the original on/brightness/colour state.
- Projection Studio's debounced save previously read `pj.cur` only when the timer fired, so switching layouts before the delay could save the wrong project. Fixed with a per-project snapshot queue and a flush before deletion; evidence: `node test/projection.js` confirms same-project edits coalesce and two projects save their own captured state.
- Native quit (including macOS Cmd+Q) could bypass the main-window close restore path, and the close path could destroy the app after four seconds while a slow restore was still running. Quit now waits for active drivers, and Projection Lights waits for in-flight writes before restoring; evidence: `node test/projection.js` verifies command ordering and idempotent concurrent Stop. Actual shutdown and bulb restoration remain unverified because Electron aborts before opening here.
- Reopening Projection Studio output could let the old window's `closed` event clear the replacement window reference. The handler now checks window identity; source syntax passes `node --check`, but reopening on real displays remains unverified without an Electron run.
- README previously said there were 21 Projection Studio animations; the current preset list contains 35. README count now matches `LumenProj.PRESET_IDS.length` (35).
- macOS does not provide system sound capture. Projection Studio now labels its Mac behavior and switches to Microphone when no system audio track is supplied; policy tests pass in `node test/projection.js`, but real Mac permissions and capture remain unverified. Effects still requires manual microphone selection.
- Local `npm test` is blocked in this environment by the WiZ simulator loopback address: it fails binding `127.0.0.70:38899` (`EPERM` sandboxed; `EADDRNOTAVAIL` unsandboxed). The hardware-free Projection Studio test passes independently.
- After `npm ci`, `npm start` exits with Electron `SIGABRT` before the UI is visible; the captured stack trace does not identify a cause. Interactive Studio behavior has not yet been observed here.
- Mac: system-sound capture for Effects is unavailable (Windows-only loopback in src/main/main.js); Mac falls back to the microphone.
- Mac: the first build (identity null, no signature) showed "Lumen is damaged and can't be opened" on the owner's Mac (reported 2026-11-15). Workaround: `xattr -cr /Applications/Lumen.app`. Fix attempted: `mac.identity` set to "-" (ad-hoc signing) in package.json; UNVERIFIED until the next release build is tried on a Mac. Even when fixed the app is not notarized, so first launch needs right-click > Open. Windows build is unsigned too (SmartScreen may warn).
- `npm test` currently covers only the 3 WiZ tests; other test files are missing from the repo.
- The Cync relay certificate is expired and mismatched; the user must tick "Trust the Cync relay's certificate" (pinned). Documented, deliberate.
- Cync allows one relay session per account; opening the Cync phone app drops Lumen's session until the next command.
- Hubspace and Cync integrations are unofficial/reverse-engineered and can break if the vendors change their cloud.
